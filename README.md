## Implemented integrity architecture

The successor currently provides:

- Language-neutral JSON Schemas for hypothesis, dataset, transformation, leakage check, evaluation boundary, analysis configuration, run metadata, analysis result, and claim status.
- Runtime contract validation.
- Centralized evidence-state and claim policy.
- Provenance validation and SHA-256 support for acquired successor inputs.
- Dataset-manifest hash binding for empirical result manifests.
- Evaluation-boundary validation for successor runs.
- Result-manifest loading and fail-closed claim-state derivation.
- Derived evidence view models for presentation.
- An active React interface that renders scientific status from those view models rather than from hardcoded validation values.

The intended evidence flow is:

```text
Hypothesis contract
  → data/provenance contract
  → evaluation boundary
  → analysis configuration
  → scientific executor boundary
  → result manifest
  → claim-state evaluator
  → derived view model
  → UI
```

The scientific executor itself is not implemented in this phase.

## Evidence states

The centralized policy supports:

- `BLOCKED`
- `ILLUSTRATIVE`
- `EXPLORATORY`
- `NEGATIVE_NULL_FAVORING`
- `EVALUATED`
- `VALIDATED`
- `UNRESOLVED`

The system is designed to fail closed. Missing evidence remains missing; null values are not converted to zeroes, and an executor or component cannot promote itself to a stronger evidence state without the required evidence chain.

## Original falsification purpose

The audited formulation is:

> Determine whether a prespecified zodiacal or independently derived astronomical-relational representation provides reproducible incremental out-of-sample predictive information beyond ordinary astronomical state, temporal or seasonal structure, and appropriate negative controls.

This is not yet an executable experiment. The following scientific decisions remain blocked:

- `UD-001`: target/outcome, unit of analysis, independent unit, population/sampling frame, and estimand.
- `UD-002`: authoritative empirical data.
- `UD-003`: primary null/control family.
- `UD-004`: evaluation and confirmatory policy.

Scientific execution remains blocked while any of these are unresolved.

## Implemented integrity architecture

The successor currently provides:

- Language-neutral JSON Schemas for hypothesis, dataset, transformation, leakage check, evaluation boundary, analysis configuration, run metadata, analysis result, and claim status.
- Runtime contract validation.
- Centralized evidence-state and claim policy.
- Provenance validation and SHA-256 support for acquired successor inputs.
- Evaluation-boundary validation for successor runs.
- Result-manifest loading and fail-closed claim-state derivation.
- Derived evidence view models for presentation.
- An active React interface that renders scientific status from those view models rather than from hardcoded validation values.

The intended evidence flow is:

```text
Hypothesis contract
  → data/provenance contract
  → evaluation boundary
  → analysis configuration
  → scientific executor boundary
  → result manifest
  → claim-state evaluator
  → derived view model
  → UI
```

The scientific executor itself is not implemented in this phase.

## Evidence states

The centralized policy supports:

- `BLOCKED`
- `ILLUSTRATIVE`
- `EXPLORATORY`
- `NEGATIVE_NULL_FAVORING`
- `EVALUATED`
- `VALIDATED`
- `UNRESOLVED`

The system is designed to fail closed. Missing evidence remains missing; null values are not converted to zeroes, and an executor or component cannot promote itself to a stronger evidence state without the required evidence chain.

## Verification commands

The branch defines these commands:

```bash
npm ci
npm run typecheck
npm test
npm run build
npm run audit:fixtures
npm run audit:provenance
npm run audit:leakage
npm run audit:claims
npm run reproduce
npm run verify
```

`npm run reproduce` reproduces the evidence-integrity state only. It does not run the BURGAMOTS scientific experiment.

`npm run verify` is fail-closed: any failing required command must produce a nonzero exit status.

Do not interpret the existence of these commands as proof that the full suite has passed. Execution results are recorded only when a tool actually runs them.
